# THE CODEX — V0.9 CAPABILITY BASELINE

**Ruling (Marcus, 2026-07-19):** This application is Version 0.9 — the recovered, working product floor.
The mission is to ship **Version 1.0**: preserve *everything* below while improving usability, cohesion,
visual design, performance, interaction quality, accessibility, maintainability, and integration.

**The success metric:** *"Is the application objectively better than the version Marcus already had?"*
Not lines rewritten. Not design purity. Not a new architecture.

**The law of V1.0:**
- Never reduce capability in pursuit of elegance.
- Never discard a working system because it doesn't match a new interface.
- The interface serves the product; the product does not serve the interface.
- If a feature worked, the default is *improve it* — never remove it.
- No feature ships as "replaced" until the replacement is verified superior for a real Dungeon Master.

## 2. AI integration (10 integration points, 27 system prompts — the crown jewels)

- **Providers:** Google Gemini (`gemini-2.0-flash` family, key in Settings, 429 backoff) + **Ollama local LLM**
  (default `gemma3-27b-abliterated`, LAN URL `192.168.1.174:11434`, model discovery via `/api/tags`,
  `/ollama` proxy for remote CORS) with automatic cross-provider fallback.
- **`src/lib/prompts.ts` (771 lines):** 27 crafted prompt generators — combat advisor, spell explainer/tactician,
  quiz master, scene coach/generator/grader, improv grader, combat sim scenario + evaluator, character setup,
  persona builder, backstory helper + drills, dialogue suggestion/practice/evaluate/quick-draw/delivery coach,
  NPC conversation drill with per-turn voice-consistency coaching, interactive one-shot (DM + coach dual role),
  condition drill generator, accent phrase generator.
- **`characterContext()`** injects the *entire* character (stats, spells, slots, weapons, features, persona,
  backstory, race rules, homebrew, campaign) into every query. This is why the AI feels like it knows the character.

## 4. Data & persistence

localStorage, local-first, per-character keys: character roster + active id, AI config, training profile
(quiz history, SM-2 flashcard state, XP/streaks), combat state (survives reload), damage logs, session RP logs,

backstories, toybox.

## 5. Polish worth preserving

Dark-fantasy grimoire language: Cinzel Decorative / Alegreya / Cinzel, gold-on-ash palette
(gold `#c5a55a`, ember, arcane, eldritch, verdant), parchment cards with corner flourishes, ornate dividers,
drop caps on AI responses, animated `codex-ritual` border on the advisor, gold text selection.
Framer Motion staggers + page transitions, dice tumble animation, `prefers-reduced-motion` respected,
haptics hook on mobile, 44px touch targets, ARIA labels, WCAG AA contrast, safe-area insets.

## 7. Release-gate audit — what this document got wrong (2026-08-17)

Four independent auditors read the current source against every claim above, and each reported
"regressions". Every one of them was then checked against the **actual V0.9 source at `798a922`**,
the commit this document was written to describe. All four turned out to be claims that were **never
true of V0.9** — dormant code, or code that never existed. **V1.0 has reduced no capability.**

This section exists because the difference matters enormously. A regression is something V1.0 broke
and must restore. An overclaim is a promise the baseline made on V0.9's behalf that V0.9 never kept —
and chasing it as a regression sends a session hunting for a deletion that never happened.

| Claim | Where | What the V0.9 source actually shows | Verdict |
|---|---|---|---|
| "initiative tracker (add/remove/reorder NPCs)" | §1 Combat Helper | `InitiativeTracker.tsx` (332 lines, complete) exists at `798a922` and is exported from `combat/index.ts` — and rendered by **nothing**. `git grep InitiativeTracker 798a922 -- src/` returns only its own definition and the barrel export. `CombatState` has an `InitiativeEntry` type but no field to hold entries. | **Never shipped.** Written, never wired. |
| Grimoire "advanced filters (concentration/ritual/casting time/10 damage types/5 range bands)" and "per-spell AI Explain and Tactics" | §1 Spellbook/Grimoire | Those features live in `Spellbook.tsx` (1,223 lines). `798a922:src/App.tsx` renders **`GrimoirePage`** on both grimoire routes and imports `Spellbook` without ever rendering it. The live surface has never had them. | **Never shipped.** Dead component. |
| Campaign data "injected into **every** AI prompt as context" | §1 Campaign Editor | `prompts.ts` accepts an optional `campaign` on every generator, but at `798a922` only three files pass one: `CampaignEditor`, `session/AIAssistPanel`, `session/EngageCard`. `CombatHelper` called `combatAdvisor(character)` then and calls `combatAdvisor(character)` now — byte-identical. | **Never shipped.** Wired for 3 of ~44 callsites. |
| "Alegreya" font · "drop caps on AI responses" · "animated `codex-ritual` border" · "gold text selection" | §5 Polish | `git grep` for `Alegreya`, `codex-ritual`, `first-letter` and `::selection` across `798a922:src/` returns **zero matches for all four**. | **Never existed.** Aspirational. |

### What this changes

Nothing above is a reason to delay a release, and none of it is a defect V1.0 introduced. But two of
the four are **finished code sitting one wiring job away from working**, which makes them the
cheapest large wins left in the project:

- `InitiativeTracker.tsx` — 332 complete lines. Needs an `initiative` field on `CombatState`, three
  handlers, and a render site. This is the one with real table value: multi-enemy turn order is
  currently pencil-and-paper.
- `Spellbook.tsx` — 1,223 complete lines carrying the advanced filters and the per-spell AI Explain /
  Tactics buttons. Needs porting into `GrimoireCard` / `GrimoirePage`, or reinstating as the prep-mode
  spell surface.
- Campaign injection needs `campaign` threaded from `App` through `Layout` to the ~41 callsites that
  currently pass character-only. Mechanical, wide, and worth doing in one pass.

All three are Wave 5 items, recorded in `docs/plans/codex-v1/00-status.md`.

**Method note for whoever audits next:** every "regression" must be checked against `798a922` before
it is called one. Four out of four failed that check this time. Read the claim, then read the commit.
